EXEMPLE DE TABLE LR, SUR UN VRAI PROGRAMME DU LANGAGE
=====================================================

Programme :

    정수를 주는 main() {
        42를 줘요.
    }

Ce que le parser reçoit du pré-parser (13 tokens) :

    정수  를  주는  Name  (  )  {  Int  를  줘요  .  }  Eof


--------------------------------------------------
1. LA GRAMMAIRE, RÉDUITE À CE QUI SERT ICI
--------------------------------------------------

Les vrais noms de RULES, mais la partie « chaîne d'appels » (Chain, EndStep,
Arguments) est raccourcie en une seule règle (11) pour que la table reste
lisible.

     0 : StartSymbol  → Items Eof
     1 : Items        → Items Item
     2 : Items        → ε
     3 : Item         → Function
     4 : Function     → FunctionHead ( Parameters ) Block
     5 : FunctionHead → ReturnType Name
     6 : ReturnType   → 정수 를 주는
     7 : Parameters   → ε
     8 : Block        → { Statements }
     9 : Statements   → Statements Statement
    10 : Statements   → ε
    11 : Statement    → Argument 줘요 OptionalDot
    12 : Argument     → Int 를
    13 : OptionalDot  → .
    14 : OptionalDot  → ε

4. LES ÉTATS (règle avec le marque-page ·)
--------------------------------------------------

Chaque ligne de la table est un de ces états.

     0 : StartSymbol → · Items Eof | Items → · Items Item | Items → ·
     1 : StartSymbol → Items · Eof | Items → Items · Item | Item → · Function
         | Function → · FunctionHead ( Parameters ) Block
         | FunctionHead → · ReturnType Name | ReturnType → · 정수 를 주는
     2 : StartSymbol → Items Eof ·
     3 : ReturnType → 정수 · 를 주는
     4 : Items → Items Item ·
     5 : Item → Function ·
     6 : Function → FunctionHead · ( Parameters ) Block
     7 : FunctionHead → ReturnType · Name
     8 : ReturnType → 정수 를 · 주는
     9 : Function → FunctionHead ( · Parameters ) Block | Parameters → ·
    10 : FunctionHead → ReturnType Name ·
    11 : ReturnType → 정수 를 주는 ·
    12 : Function → FunctionHead ( Parameters · ) Block
    13 : Function → FunctionHead ( Parameters ) · Block | Block → · { Statements }
    14 : Block → { · Statements } | Statements → · Statements Statement
         | Statements → ·
    15 : Function → FunctionHead ( Parameters ) Block ·
    16 : Block → { Statements · } | Statements → Statements · Statement
         | Statement → · Argument 줘요 OptionalDot | Argument → · Int 를
    17 : Block → { Statements } ·
    18 : Argument → Int · 를
    19 : Statements → Statements Statement ·
    20 : Statement → Argument · 줘요 OptionalDot
    21 : Argument → Int 를 ·
    22 : Statement → Argument 줘요 · OptionalDot | OptionalDot → · .
         | OptionalDot → ·
    23 : OptionalDot → . ·
    24 : Statement → Argument 줘요 OptionalDot ·

Comment on remplit la table à partir des états :
    - shift  : · devant un terminal ; l'état où mène ce terminal
    - GOTO   : · devant un non-terminal ; l'état où mène ce non-terminal
    - reduce : · en fin de règle ; dans la colonne de chaque token qui peut
               suivre (le lookahead)
    - accept : StartSymbol → Items · Eof, sur Eof

--------------------------------------------------
6. CE QU'IL FAUT REMARQUER
--------------------------------------------------

- Une réduction se fait toujours en deux temps : dépiler autant d'états que
  la règle a de symboles à droite, puis lire GOTO[nouveau sommet, partie
  gauche]. Pour une règle vide (lignes 1, 9 et 12), on ne dépile rien.

- C'est à chaque réduction qu'on construira l'AST : ligne 15 l'argument 42,
  ligne 19 l'instruction de retour, ligne 23 la fonction main.

- Le même token n'a pas le même sens selon l'état : 를 vaut s8 dans l'état 3
  (le 를 de 정수를) et s21 dans l'état 18 (le 를 de 42를). C'est l'état qui
  sait où on en est.

- Les erreurs sont gratuites : avec 정수를 main() (주는 oublié), on arrive dans
  l'état 8 avec le token Name ; la case est vide, donc erreur, et la ligne 8
  dit que le seul token attendu est 주는.

- La vraie table a la même forme, avec toutes les règles de RULES : une
  colonne par terminal (environ 60), une par NTerm (46), et quelques centaines
  de lignes.
